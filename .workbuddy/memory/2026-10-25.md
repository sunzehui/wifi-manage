# 2026-10-25

## 安卓 App 连不上设备后台 —— 根因与修复

**设备**: 随身 WiFi LV01 / MF518A03_CN_MGX-V5.8.2，后台 192.168.1.1，realm=Highwmg，账号 admin。
设备 Digest 方案（非标准）：登录 HA2 = md5("GET:/cgi/protected.cgi")；数据请求 HA2 =
md5(method + ":/cgi/xml_action.cgi")，且 Authorization 头的 uri 固定写 `/cgi/xml_action.cgi`
（不看真实 URL）。原厂实现见设备 `/js/base/utils.js` 的 doLogin / getAuthHeader。

**根因**：设备 httpd **同一时刻只允许一个管理会话**。任何一次新登录都会把既有会话踢掉，
被踢客户端之后一直返回 `<RGW><login_status>KICKOFF</login_status></RGW>`。
网关 `login()` 用 `if (!session.nonce)` 判断，WebView 每次换页 / 每次失败重试都会重新登录，
于是自己把自己踢死；实测连续登录后连电脑端 PHP 也取不到数据，需断电重启才恢复。

**PHP 版为何能用**：`server.php` 把 realm/nonce/nc 存进 session 文件（`saveSession`/`hasSession`），
只在没有会话时登录一次，后续请求复用 —— 不产生多余登录。

**另一处 bug**：`ok()` / `xmlOk()` 只把 `UNAUTHORIZED` 当失败，`KICKOFF` 被当成成功，
于是所有字段解析为空、界面显示"未联网"却不报错（静默失败）。

**已改**：
- `public/gateway.js`：新增 localStorage 会话持久化（`mifi_session`，30min TTL）+ `ensureSession()`/
  `invalidateSession()`；鉴权类失败（KICKOFF/UNAUTHORIZED/LOCK）只做指数退避，**不再连环重登**；
  仅网络类失败才重登一次。`ok()` 增加 `AUTH_FAIL` 正则，错误信息按 reason 区分。
- `server.js`：同步 `xmlOk` 的 AUTH_FAIL 判定与错误文案。
- 重新构建并安装 APK → 手机端已正常显示（已联网 / 4G LTE / 信号 -79dBm / 电池 30%）。

**注意**：设备被多次登录"踢死"后不会短时间自愈，需断电重启随身 WiFi。

## 「获取平台剩余流量」报错 —— 两个 bug（APK 专属）

现象：流量页「套餐流量（发卡平台）」显示 "获取失败: cfg is not a function"。

1. `public/gateway.js` 的 `remoteTraffic()` 里 `const cfg = cfgsafe()` 把对象赋给 cfg，
   后面却写成 `cfg().host` → TypeError。改为直接用 `cfg.host`，抽出 `mgxGet()/parseLooseJson()`。
2. 修掉 TypeError 后仍会失败：WebView 里 `fetch` **读不到 `Set-Cookie`**（浏览器禁止读取该
   响应头），也发不出手工设置的 `Cookie`（禁止的请求头）；平台下发的
   `Path=/kyhl-weixin-1.0` 与代理路径 `/mgx/...` 也不匹配，浏览器永远不会回传。
   于是第二个请求 `findCardInfo.do` 必定返回 `system_result_key=7 / session过期`。

修法：会话改由 Java 代理保管。`MainActivity.LocalProxy` 新增 `mgxSession`，
/mgx/ 响应里抓 `Set-Cookie` 的第一段存下（`firstCookiePair`），后续 /mgx/ 请求若浏览器
没带 Cookie 就补上；不再把平台 Set-Cookie 转发给浏览器。gateway.js 侧增加
"session过期 → 重登一次再取" 的兜底与可读错误文案。

**结论**：PHP / Node 版一直是好的（服务端自己处理 cookie），只有 APK 走 WebView 才踩到。
验证：APK 总量 1500 GB / 已用 15.89 GB / 剩余 1484.11 GB；Node 版同口径一致。

## 首页电池卡新增「剩余续航」（待统一测试）

公式：放电速率 `r = (起始电量 − 当前电量) / 已用时长`（%/小时），剩余续航 `T = 当前电量 / r`。
基准点首次运行用 `09:00 / 75%` 打底（常量 `BATT_SEED_HOUR/BATT_SEED_PCT`），之后按真实采样累积；
电量回升判定为充过电 → 结束本轮、把速率存 `batt_last`，充电期间用该速率继续估算。
采样存 localStorage：`batt_run`（本轮，24h/240 点）、`batt_last`、`batt_seeded`。

改动文件：`public/index.html`（电池行加 `.battery-eta` 两个节点 + 计算逻辑 `battUpdate/battRate/battEta`，
挂在 `renderRest` 的电池分支）、`public/app.css`（`.battery-eta` 样式）。

按 09:00→14:37、75%→30% 计算：337 分耗 45% → 8.01 %/时 → 剩 30% 约 **3 小时 45 分**。

**注意**：当时设备处于「充电中」，所以界面上会显示 `约 3 小时 45 分 / 充电中 · 8.0 %/时`。
用户要求先不测，等代码全部写完再统一测——APK 尚未用最终版逻辑重建。

## App 图标（Launcher icon）

原来 `AndroidManifest.xml` 没有 `android:icon`，装完是安卓默认小机器人。现补上：
图标用 PIL 程序化生成（`android/tools/make_icon.py`，4096 超采样后 LANCZOS 缩小）。
设计：深蓝底 `#0d1322→#1b2440`（同 `--bg/--card2`），WiFi 三层圆弧 + 圆点，
描边用 `--good #34d399 → --blue #60a5fa` 竖向渐变，圆角 22.5% + 极淡顶部白色柔光。

产物：`android/res/mipmap-{m,h,xh,xxh,xxxh}dpi/ic_launcher.png` + `ic_launcher_round.png`（圆形遮罩版）；
网页端 `public/icon.png`(1024)、`public/apple-touch-icon.png`，三个页面加了 favicon/theme-color。

构建脚本关键改动：`build-apk.sh` 必须先 `aapt2 compile --dir res -o res.zip`，再
`aapt2 link ... -R res.zip`（aapt2 不能把 res 目录直接丢给 link）。
已构建通过（APK 53K→166K），`aapt2 dump badging` 确认各密度图标齐全。

# 01: 打通通知链路（端到端最小内容）

**What to build:** 手机装上重新构建的 APK、连上随身 WiFi 打开首页后，通知栏出现一条属于本应用的通知（内容先占位：应用名 + 一行「已连接」级别的示意文字），首页每轮状态轮询都把它刷新一次；同时电脑/平板上的网页版打开任何页面都不因这座桥产生报错。这张票的价值是「管道全通」——原生通知器、WebView 双向桥、页面侧调用、构建与权限一次穿透，真实字段留给 02。

必须先解决的既有事实：免 Gradle 的构建脚本目前**只编译单个 Kotlin 源文件**，新增的原生文件会被静默漏出 dex，所以「编译整个源码目录」是这张票的第一件事，否则后面每一步都验证不到东西。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 构建脚本改为编译 APK 壳目录下全部 Kotlin 源文件，构建产物里能确认新增类已进入 dex（而非仅构建返回 0）
- [ ] 清单声明通知权限；在 targetSdk 仍为 28 的前提下不写运行期申请，但在 README 待办处留一句「提 targetSdk 到 33+ 时需补运行期申请」
- [ ] 原生侧建通知渠道（API 26 以下走无渠道分支）、固定通知 id、纯色 alpha 的状态栏小图标；渠道静默、importance 低、`setOnlyAlertOnce`
- [ ] `@JavascriptInterface` 回调不在主线程，投递通知前切主线程
- [ ] 页面侧桥封装：原生桥不存在时整条路径静默跳过（网页版零行为变化）
- [ ] 首页状态轮询的成功回调里推送一次；轮询本身仍是既有那一个 5s 请求，**不新增任何设备请求**
- [ ] 自动化证据：构建脚本跑通且 dex 含新类；三个页面脚本与网关脚本语法检查通过；用浏览器以 `file://` 加载首页（此时原生桥缺失）断言页面错误收集数组仍为空
- [ ] 真机肉眼（需用户装 APK 确认）：下拉通知栏看到这一条；logcat 里推送计数 30 秒约 6 次；点通知能拉起应用

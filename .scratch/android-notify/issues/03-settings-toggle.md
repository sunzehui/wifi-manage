# 03: 设置里的通知开关与撤条时机

**What to build:** 用户在右上角设置弹窗里能看到「通知栏显示状态」这一项，**默认开启**（装这个应用就是为了瞟一眼状态）；关掉后通知栏那一条条立刻消失，之后无论怎么轮询都不再出现；打开时恢复。从最近任务里划掉应用后，通知栏不该留下一条还在报旧数据的假状态。

需要注意的既有行为：设置弹窗的保存动作是**靠重新加载页面生效**的，所以「关闭即撤条」必须发生在重新加载之前，否则新页面已卸载、没人去撤那条。

**Blocked by:** 02: 通知栏显示真实状态与呈现质量

**Status:** ready-for-agent

- [ ] 设置弹窗新增开关项，读写本地持久化配置，与既有设备密码/服务器地址项同风格
- [ ] 默认开启；首次安装即有通知，不需要用户先找到开关
- [ ] 关闭后在保存并重新加载页面之前就完成撤条，通知不会在重载后自己长回来
- [ ] 原生侧在 Activity 销毁时撤条；仅在开关为关或应用真死时通知消失
- [ ] 开关状态跨重启保持（与既有连接设置一样存在本地）
- [ ] 真机肉眼：关掉开关后通知在数秒内消失；重装应用默认出现；从最近任务划掉后通知不残留
- [ ] 自动化证据：脚本语法检查通过；构建产物中的页面脚本包含该开关（确认 assets 合包为新版）

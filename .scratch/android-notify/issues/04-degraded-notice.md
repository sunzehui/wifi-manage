# 04: 取不到数据时通知就地降级

**What to build:** 当设备不可达、密码填错、会话被踢（KICKOFF）、设备登录锁定时，通知栏**那一条**就地变成降级文案——标题带异常标记、正文给出页面已经拿到的具体原因，时间戳停在最后一次成功之外的一刻，让用户不看屏幕也知道「现在读不到设备，原因是 X」。明确**不新增第二条告警通知**（本轮选定的形态是常驻一条，异常也复用它）。

可复用的既有事实：页面侧已经把这些原因归好类并显示在顶部横幅上（含「设备不可达」这条路径），降级只需在同一条已推送的载荷里把 `bad` 置真并复用现成文案，不需要新增判定逻辑，也不需要新增请求。

**Blocked by:** 02: 通知栏显示真实状态与呈现质量（与 03 无依赖，可并行）

## 验证记录（2026-10-29）

- 挂点：降级推送加在 `public/app.js` 的 `showErrorBanner(msg)` 末尾——这正是三个页面轮询失败已有的唯一收口，不新增判定、不新增请求；标题前缀「⚠ … 设备不可达」，正文 `line1` 原样复用横幅那句原因
- 只此一条：走同一个 `Native.push` → 同一个 `NOTIF_ID`，vm 桩桥断言失败分支只产生一次 `updateStatus` 调用且 `bad === true`
- 异常标记：页面侧标题前缀 ⚠；原生侧 `bad` 时标题染 `#E53935`（不用 CSS 那个浅红 `--bad`，通知栏底色不归我们管）并套 `BigTextStyle`，让「设备登录已锁定…」这类长句展开后读得全；渠道仍是 `IMPORTANCE_LOW` + `setOnlyAlertOnce`，所以降级同样静音、不振动、不弹横幅
- 清除：恢复后成功回调推的正常载荷 `bad:false`，原生不再染色也不套 BigText，同 id 覆盖即抹掉异常标记
- 不额外请求设备：失败分支只是把页面已经拿到的 `e.message` 递过桥，登录退避与会话复用逻辑一行没动
- 代码评审后的修正两处：(1) 原实现每次失败轮询都推 `ts: Date.now()`，相对时间永远归零，违反本票「时间戳停在最后一次成功之外的一刻」——改为 `Native` 记住最后一次成功推送的 `ts`，降级载荷沿用它；(2) 降级只有首页能自愈（二级页面没有 status 轮询，推完没人更正），故 `showErrorBanner(msg, notify)` 只在 `startPolling` 拉的是 `/api/status` 时传真；标题也从写死的「设备不可达」改为「状态读取失败」，因为 KICKOFF/锁定并不是不可达
- **仍欠手机**：关 WiFi / 填错密码后的肉眼降级与恢复——手机已摘下 USB。接回后走 `/tmp/verify0304.sh` 阶段 4/5，用「服务器地址填 `http://127.0.0.1:1`」制造失败（连接立刻被拒，完全不碰设备登录，不会把唯一管理会话踢死），验完再清空恢复
